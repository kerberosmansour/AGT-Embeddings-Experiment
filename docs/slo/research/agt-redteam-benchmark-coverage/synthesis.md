# Synthesis — AGT Red Team Benchmark Coverage Expansion

The current 24-scenario benchmark is a good smoke suite because it proves the schema, harness, scorecard, hygiene gate, OpenCRE validator, product renderer, and live-sandbox path all work end to end; it is not a strong measurement corpus because four rows per trap class cannot support stable catch-rate or false-positive claims, so the design must handle separate smoke and measurement suites because the repo-local scenario inventory is balanced but intentionally small.

The measurement suite should add negative examples as first-class rows, not as afterthoughts: four hard-benign and four near-miss rows per trap class gives every class a false-positive denominator while keeping the suite reviewable, so the design must handle `positive | hard_benign | near_miss` labels because the current schema and reports primarily exercise trap-positive rows.

A 120-row target is the right **core** measurement suite, not a hard ceiling: after incorporating the founder-supplied Agentic Scorecard draft and the prompt-injection corpus lesson, the 72 positive rows must be split into 24 canonical positives and 48 evasion positives, not treated as undifferentiated attacks; the design must also permit targeted extension packs when a control/evasion metric cell is underpowered because the pasted Agentic Scorecard draft emphasizes static/mock/live testing tiers and the prompt-injection corpus pattern shows that canonical attacks alone do not measure control robustness.

The benchmark should report catch rate, evasion catch rate, evasion degradation, false-positive rate, and utility-preservation rate by trap class and by AGT-AC control, not just a single aggregate score; a single score would hide whether a control fails on memory, A2A, approval, hidden-content traps, or simple evasion variants, so the design must handle per-class, per-control, and per-evasion-family metrics and must flag low-power cells instead of squeezing them into a fixed row budget because the current control catalog covers 15 AGT-AC controls with uneven scenario counts.

The OpenCRE mapping layer should remain candidate-honest while coverage expands: unverified mappings must stay `candidate` until backed by committed OpenCRE references, so the design must handle mapping confidence separately from benchmark performance because `docs/slo/research/agtrt-opencre-relations.md` says every current relation is effectively candidate.

Live L3 should be sampled, not applied blindly to every row: the M6 path proves real-agent assessment can be safe, but each live run has cost, sandbox, and key-management overhead, so the design must handle L3 as a representative escalation layer because `docs/slo/completion/agtrt-m6.md` records one successful live trace, not a broad live study.

The first coverage write-up did not explicitly factor the Agentic Scorecard draft deeply enough; it captured the three-tier evidence posture but missed the evasion-resistance measurement axis. The next SLO work should therefore be a focused follow-up runbook or ticket series for an AGT Red Team Measurement Suite v2: add `scenario_kind` and `evasion_technique` labels, author the 120-row core suite with 48 explicit evasion-positive rows, add an evidence-power check for undercovered cells, allow targeted extension packs beyond 120 when needed, extend scorecard metrics for evasion degradation, and gate hard-benign / near-miss false positives, so the design must handle expansion as a measured second phase because the completed runbook explicitly shipped an instrument, not an exhaustive study.
